1. CLAUDE.md: add a section `## minos-store` directly before `## minos-sandbox`. State, as built: `Ledger` (`append`, `read`) and `Blobs` (`put`, `get` with a size cap, `contains`) are synchronous traits with `&self` methods, implemented by `MemoryStore` (tests above the store, LOOP-09) and `FileStore`, and later by DynamoDB and S3; both pass one contract test file. The file store lives in `<project>/.minos/` (created 0700, a symlinked root refused, on the source denylist): `runs/<run-hex>/ledger.jsonl` per run and `blobs/sha256/<2 hex>/<62 hex>` shared by every run, judge data included (D-10). Every append takes an exclusive `std::fs::File::lock` on `runs/<run-hex>/ledger.lock`, rebuilds the key set from the file under the lock, writes one line, and calls `sync_data` before returning (D-11, D-12); reads take a shared lock. An append whose key exists writes nothing and returns `Duplicate` (equal record) or `Conflict` (different record; first write wins). A torn tail is tolerated: `read` reports it as a count and the next append truncates only it; invalid JSON elsewhere, a key mismatch, a seq gap, an over-cap line, and an unknown `v` refuse the ledger (D-13). Blobs are written temp-then-rename in their shard directory and rehashed on every read; a put heals a tampered blob. Phase 7's whole-run `driver.lock` (LOOP-06) is a separate file.
