<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ledger fold -> loop decisions | The loop acts only on what the fold derives; a resumed session must choose the same next step as an uninterrupted one |
| loop -> observer (Phase 8 terminal) | Events cross to a printer; they must carry no sandbox or model text |
| job runner -> loop | Results and failures cross the seam with blame attached |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-07-01 | Tampering | Resume chooses a different step than an uninterrupted run (LOOP-05) | high | mitigate | `next_step` is pure over the order-independent fold; proptests prove permutation invariance, progress, and termination |
| T-07-07-02 | Information disclosure | Hostile text reaching a terminal through observer events or errors | high | mitigate | `LoopEvent` and `DriverError` carry IDs, numbers, closed enums, and validated `Outcome`/`Decision` values only; no `String` payload from a sandbox or model |
| T-07-07-03 | Denial of service (billing) | An infrastructure failure misclassified as a configuration error or vice versa | medium | mitigate | `JobFailure` and `DriverError` separate `Infra` (retried, breaker-counted) from `Config` (stop, record nothing) by type, documented per variant (D-16) |
| T-07-07-04 | Elevation of privilege | The loop linking sandbox or backend code | medium | mitigate | `minos-loop` depends only on core, store, propose (Cargo.toml grep plus `cargo deny check`); the seam is defined here and implemented in the CLI |
</threat_model>
