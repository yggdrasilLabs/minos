    Read the proposed signatures and their semantics, then approve or describe changes.

    1. In `minos_sandbox::untrusted` (re-exported at the crate root):
       - `pub enum SinkError<E>` (`#[non_exhaustive]`, Debug, thiserror), three variants, no payload but the store's own error:
         `Repack` ("the candidate's out/ files could not be re-packed"; the runner records it as `Rejected(OutputInvalid)`, never retried),
         `DigestMismatch` ("the store named the blob by a digest other than its content's"; an infrastructure fault),
         `Store(E)` ("the blob store failed"; the store's error, retried if the store says so).
    2. `impl Untrusted<GuestOutput<Candidate>>` (candidate output only):
       `pub fn store_judge_input<E>(self, store: impl FnOnce(&[u8]) -> Result<BlobId, E>) -> Result<BlobId, SinkError<E>>`
       - Keeps only files whose path starts with `out/`, in path order. Drops everything else: the status, the build and run logs, `diffs/`, a scorecard-shaped file, any other name.
       - Writes them as a canonical ustar archive: regular files, mode 0644, mtime, uid, and gid 0, empty owner and group names, then two 512-byte zero end blocks. No other entry. An output with no `out/` file becomes the empty archive (1024 zero bytes). The size is bounded by construction: a subset of a stream that already passed `MAX_CANDIDATE_OUT_BYTES`.
       - Hands the bytes to `store` once. Returns `BlobId::of(bytes)` only after checking that `store` returned the same ID, else `DigestMismatch`.
       - The judge VM unpacks this blob under `/candidate`, so the judge reads `/candidate/out/<file>`.
    3. `impl<R: Role> Untrusted<OutputFile<R>>` (any role):
       `pub fn store_tail<E>(self, max: usize, store: impl FnOnce(&[u8]) -> Result<BlobId, E>) -> Result<BlobId, SinkError<E>>`
       - Hands the last `min(max, MAX_STAGE_LOG_BYTES)` bytes, unsanitized, to `store` once. The same digest check applies. Readers turn the blob into text only through `LogExcerpt::from_bytes` (D-09).
    4. What does not change: `Untrusted` keeps one private field and still has no Debug, Display, Deref, Clone, or Default. Both exits consume `self` and return only a `BlobId`. A new compile-fail case proves judge output has no `store_judge_input`. The only production caller is `minos-runner`, which passes its `Blobs::put`. The LOOP-01 grep check (07-12, 07-17) fails if any other crate's `src/` calls either exit.
    5. Be aware of one property before you approve. The closure sees the bytes, as any put interface must. The guarantee is that the exit never returns bytes as a value, not that the caller cannot look at them. The alternative is a `minos_sandbox::BlobSink` trait with one `put(&self, &[u8]) -> Result<BlobId, Self::Error>` method in place of the closure. It moves the same data the same way.

    Reply "approved" to implement exactly this, "approved with BlobSink" for the trait form, or describe the changes you want.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| candidate VM output -> runner | Hostile tar stream, already parsed by `Finished::into_output` under caps; leaves only through `Untrusted` exits |
| candidate artifacts -> judge VM | The repacked `out/` files become the judge's `candidate_out` section; the judge VM is the next consumer of hostile bytes |
| stage logs -> blob store -> readers | Raw capped tails are stored; readers render them only through `LogExcerpt` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-04-01 | Elevation of privilege | A new `Untrusted` exit weakening the wrapper | high | mitigate | Blocking user checkpoint on exact signatures before code (D-17); exits consume `self`, return only `BlobId`, add no Debug, Display, Deref, or Clone; role-specific impl blocks; trybuild proof for judge output |
| T-07-04-02 | Tampering | Candidate passes its status, logs, or forged scorecard to the judge | high | mitigate | Only `out/` files are repacked; the prefix test requires `out/`; a test asserts status, logs, `diffs/`, and `scorecard.json` are dropped |
| T-07-04-03 | Tampering | Non-canonical archive metadata (modes, owners, mtimes) reaching the judge | medium | mitigate | Hand-built ustar headers with fixed mode 0644 and zeroed metadata; golden BlobId pin over a fixed repack |
| T-07-04-04 | Denial of service | Oversized judge input or log blob | medium | mitigate | The repack is a subset of an output already capped at `MAX_CANDIDATE_OUT_BYTES`; `store_tail` clamps to `MAX_STAGE_LOG_BYTES` |
| T-07-04-05 | Information disclosure | Raw log bytes reaching a terminal or prompt | high | mitigate | Raw tails exist only as blobs; CLAUDE.md and the exit docs require `LogExcerpt` for every reader; 07-10's history reader uses it |
| T-07-04-06 | Tampering | A store naming a blob by the wrong digest | low | mitigate | The exit computes `BlobId::of(bytes)` and refuses a different returned ID with `DigestMismatch` |
</threat_model>
