Output: `Blobs::put_reader` on both stores, `FileStore::verified_path`, contract and file tests, and the CLAUDE.md store section.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| builder output -> store | The root image bytes come from the user's Dockerfile through the packer |
| store path -> VM launcher | The path the helper opens must be the blob the digest names |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05-01 | Tampering | A symlink or swapped file in the blob tree redirecting the helper to another host file | high | mitigate | verified_path checks every directory with symlink_metadata, matches device and inode between the checked path, the opened handle, and the canonical path |
| T-05-05-02 | Tampering | A partial blob visible after a crash | medium | mitigate | Temp file in blobs/staging, sync, rename into the shard, fsync staging and shard |
| T-05-05-03 | Denial of service | An unbounded stream filling the disk | medium | mitigate | take(max + 1) and PutTooLarge; the temporary file is removed on drop |
| T-05-05-04 | Tampering | A blob modified on disk after env build verified it | medium | accept | D-14 accepts no per-launch rehash; the store root is 0700 and owned by the user; a get still rehashes for every other reader |
</threat_model>
