<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| minos -> user's claude binary | The trusted host runs the user's own binary; the model never runs in a sandbox and no credential passes through Minos |
| claude result -> loop | The classified response is the only thing that leaves; stderr never does |
| filesystem between calls | The updater can move or delete the binary mid-run |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-07-01 | Elevation of privilege | Hostile project hooks, `.mcp.json`, or CLAUDE.md running during a proposal | high | mitigate | Each call runs in a fresh empty 0700 directory under a work root already checked to be outside any project, with `--safe-mode`, `--strict-mcp-config`, and an empty `--mcp-config`; the live suite in 06-08 proves it with canaries and a positive control |
| T-06-07-02 | Spoofing | Binary changed mid-run (update, replacement) without re-verification | medium | mitigate | `locate` before every call; a changed target must pass `reverify` (version and auth) before use; a vanished binary is an infrastructure failure |
| T-06-07-03 | Information disclosure | Credentials or account data leaving through Minos | high | mitigate | Six-variable environment only; the provider never reads credential files or variables; `auth status` PII is never bound; errors carry closed causes only |
| T-06-07-04 | Denial of service | A stuck call or flood of output | high | mitigate | `CALL_DEADLINE` (15 min) with process-group SIGKILL and `MAX_ENVELOPE_BYTES`, through 06-06's runner |
| T-06-07-05 | Repudiation | Design of record diverging from the code | low | mitigate | Task 3 rewrites the provider section from the shipped code in the same plan, with greps for each fact |
</threat_model>
