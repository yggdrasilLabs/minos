2. `#[must_use] pub enum Appended { New { seq: u64 }, Duplicate { seq: u64 }, Conflict { seq: u64 } }` (Debug, Clone, Copy, PartialEq, Eq) with `pub const fn seq(&self) -> u64`. Doc each variant: New was written at `seq`; Duplicate means the same key and an equal record already sit at `seq`, so nothing was written (the STORE-03 no-op); Conflict means the same key with a different record sits at `seq`, nothing was written, and the caller has a bug (first write wins; RESEARCH Pitfall 4).

3. `pub struct LedgerRead { lines: Vec<Line>, torn_tail: u64 }` with a `pub(crate) fn new(lines: Vec<Line>, torn_tail: u64) -> Self` and accessors `lines(&self) -> &[Line]`, `into_lines(self) -> Vec<Line>`, `records(&self) -> impl Iterator<Item = &Record>`, `torn_tail(&self) -> u64` (number of incomplete tail lines dropped, 0 or 1; never their bytes, 04-CONTEXT D-13).

4. `#[non_exhaustive] pub enum CorruptKind` (Debug, Clone, Copy, PartialEq, Eq, thiserror::Error): `UnknownVersion` (a record's `v` tag is not one this build reads; upgrade minos), `BadJson` (a complete line is not a ledger line), `KeyMismatch` (Line::verify failed: the line was edited or belongs to another run), `SeqGap { expected: u64, found: u64 }`, `LineTooLong { bytes: u64 }`.

5. `#[non_exhaustive] pub enum StoreError` (Debug, thiserror::Error), every variant documented: `Io { op: &'static str, #[source] source: std::io::Error }` (infrastructure; retried); `Corrupt { run: RunId, line: u64, kind: CorruptKind }` (line is 1-based; the ledger is refused and needs a human, D-13); `LedgerTooLarge { run: RunId, bytes: u64, max: u64 }`; `Encode(#[source] serde_json::Error)` (serializing a line failed); `BlobMissing { id: BlobId }`; `BlobTooLarge { id: BlobId, size: u64, max: u64 }` (checked before reading); `BlobTampered { id: BlobId }` (the stored bytes do not hash to their ID); `Unsafe { what: &'static str }` (a store path is a symlink or not the expected file type); `Poisoned` (an in-memory lock was poisoned by a panic; fail closed). 6. `pub trait Ledger { fn append(&self, run: &RunId, record: Record) -> Result<Appended, StoreError>; fn read(&self, run: &RunId) -> Result<LedgerRead, StoreError>; }` and `pub trait Blobs { fn put(&self, bytes: &[u8]) -> Result<BlobId, StoreError>; fn get(&self, id: &BlobId, max: u64) -> Result<Vec<u8>, StoreError>; fn contains(&self, id: &BlobId) -> Result<bool, StoreError>; }`. Each method documents its contract and has an `# Errors` section. A run that has never been appended to reads as zero lines and torn 0. Blobs stay in-memory byte slices in this phase: core exposes only `BlobId::of(&[u8])`, so a streaming put would need a core constructor (RESEARCH Open Question 3, decided: not in Phase 4; the snapshot is capped at 64 MiB).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| loop -> ledger | Every effect is keyed by content ID; a resumed step re-appends and must change nothing |
| caller -> blob reads | A caller-supplied cap bounds what a read may copy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-02-01 | Tampering | A same-key append overwriting history | high | mitigate | Duplicate and Conflict both write nothing; first write wins; contract test and property pin it |
| T-04-02-02 | Repudiation | A conflicting re-append vanishing silently | medium | mitigate | Appended::Conflict is returned and must_use, so the loop sees it (Pitfall 4) |
| T-04-02-03 | Denial of service | get copying an unbounded blob | medium | mitigate | Size over max refused before copying |
| T-04-02-04 | Tampering | Memory store diverging from the file store's semantics | medium | mitigate | One contract file runs both; the file arm arrives in 04-05 |
| T-04-02-05 | Denial of service | A poisoned mutex panicking on lock | low | mitigate | PoisonError maps to StoreError::Poisoned (fail closed, no unwrap) |
</threat_model>
