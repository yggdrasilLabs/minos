<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI composition -> runner and loop | The only place concrete backend and store types meet; errors cross with their blame |
| guest VMs -> host | The real hypervisor boundary the test exercises; output crosses only through the runner's `Untrusted` handling |
| test environment variables -> test | `MINOS_*` are read only by ignored tests, never by production code |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-14-01 | Denial of service (billing) | Infra and config failures swapped at the adapter | medium | mitigate | `failure` maps by `RunnerError::is_infra` only; unit-tested both ways |
| T-07-14-02 | Information disclosure | Judge data reaching the candidate VM on real hardware | high | mitigate | The VM test runs the production runner, which attaches judge data only through `secrets`; the candidate test proves the judge consumed the repack, and 07-12 proves the file set |
| T-07-14-03 | Elevation of privilege | Production code reading the test-only `MINOS_*` variables | medium | mitigate | Only `tests/runner_vm.rs` reads them; minos-cli's src reads none (grep in 07-17) |
| T-07-14-04 | Spoofing | The probe's new scorecard form leaking into a real image | low | accept | `minos-probe` is a test fixture binary placed only in the test rootfs; documented as fixture-only |
| T-07-14-05 | Repudiation | Claiming the VM proof without a run | medium | mitigate | Task 3 records the verbatim output with `3 passed`; the plan stops and reports if the host cannot run VMs |
</threat_model>
