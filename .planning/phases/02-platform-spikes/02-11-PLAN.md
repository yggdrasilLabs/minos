### E-2: ### The model stays outside the sandbox, replacement for `There is no API key anywhere.`

~~~markdown
Minos never reads, stores, or forwards a model credential. Models are reached through a `ModelProvider` abstraction in `minos-propose`. In v1 the personal default execs the user's own unmodified `claude` binary in print mode (02-SPIKE-EVIDENCE.md SPIKE-07 contract): the canonical binary under `~/.local/share/claude/versions/`, never whatever `claude` is first on `PATH` (it may be a wrapper that injects settings), run from a fresh empty directory outside any repository, with the environment cleared to `HOME`, `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, `USER`, `LOGNAME`, `TMPDIR`, and `LANG`, the prompt on stdin, and `{the argv from the SPIKE-07 contract}`. Its `structured_output` is model output and is parsed strictly; only token counts are recorded, never the CLI's dollar estimate. Anthropic's terms allow this only for a user running their own install under their own subscription. Shared or hosted use goes through an API-key or Bedrock provider, later implementations of the same abstraction; on AWS the agent loop calls Bedrock with the function's IAM role.
~~~

### E-3: ## Code rules, new bullet

~~~markdown
- **No tokio in v1.** No `minos-*` crate depends on tokio; v1 is synchronous (`std::process`, `std::thread::scope`, `std::os::unix::net`, `std::fs::File::lock`). The pinned VMM links tokio internally through `msb-imago`, and `deny.toml` fences tokio to that one edge, so a `minos-*` crate that adds it is refused. The AWS milestone revisits this.
~~~

### E-4: ## Local backends, three bullets

~~~markdown
- libkrunfw comes from the Homebrew tap `libkrun/krun` (`brew tap libkrun/krun`, `brew trust libkrun/krun`, `brew install libkrunfw`); Minos needs only libkrunfw from it, not libkrun, krunkit, or krunvm ({H-01}). `minos-vmm` loads it by absolute path and checks its SHA-256 first.
- libkrun's networking default is not air-gapped: upstream libkrun turns on TSI, which proxies guest INET sockets through the host, whenever no virtio-net device is configured. Minos drives libkrun through `msb_krun`, which reverses that default (`inet_hijack` off). `msb_krun`'s `net` feature stays off, `crates/minos-vmm/clippy.toml` bans the hijack, port-remap, virtio-fs, non-raw-format, guest-environment, and host-console methods (D-PROBE), and the egress test shows every guest `connect()` failing, to loopback, the LAN, and public IPv4 and IPv6, with no host canary seeing a connection ({S02-EGRESS}).
- Guest output reaches the host over a vsock port that `msb_krun` maps to a host Unix socket (`unix_connect`). The host binds the listener before launch, keeps the socket path under 104 bytes, and reads each connection through a byte cap, dropping the stream at the cap ({S03-WITHIN}, {S03-OVER}; {K4-THROUGHPUT: MiB per second} for 64 MiB).
~~~

### E-5: ## Environments and source, new paragraph after **Environment.**

~~~markdown
**Root images.** Any OCI builder that can export a rootfs tar works (02-CONTEXT.md D-14). The checked tool chain is the Docker CLI with BuildKit, `docker buildx build --platform linux/arm64 --output type=tar,dest=<file> <context>`, after which Minos's own pure-Rust packer (`minos-backend-krun`, gzip SquashFS) adds `/init` and writes the raw read-only root image ({RI-03}, {S06-BOOT}). Docker Desktop is one way to get that builder, not a requirement; lima, podman, and Apple's container tool are untested alternatives. Base images are pinned by digest. Two builds of the same Dockerfile {matched, or differed because <cause>} ({RI-04}); byte-identical images and `minos.lock` are Phase 5 (D-16).
~~~
