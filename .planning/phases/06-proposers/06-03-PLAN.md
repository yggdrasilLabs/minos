<objective>
Build deterministic prompt assembly for the single-shot tier: the history view (rows rendered from recorded outcomes with held-out values excluded by construction), the stable prefix, the dynamic suffix with untrusted, fenced failure excerpts and the user's notes last, and the tests that prove determinism, prefix stability, fence integrity, and held-out non-interference.

Purpose: PROP-05 and PROP-06. The prompt is hashed into `PromptHash` for `Origin::Model`, so its bytes must be a pure function of its inputs, and it must never carry a held-out metric (PITFALLS 11) or let sandbox text pose as instructions (PITFALLS 13).
Output: `prompt.rs` with `assemble`, `prompt/history.rs`, three test targets, one golden snapshot.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sandbox logs -> prompt | Failure excerpts are text a candidate controls; they enter only as `LogExcerpt` inside untrusted fences |
| earlier model output -> prompt | Rationales are model text; accepted writable files may hold model-written content |
| judge results -> prompt | Scorecards include held-out metrics that must never reach the proposer |
| user notes -> prompt | Steer notes are the user's own text, sanitized and placed last |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-03-01 | Tampering | Prompt injection through logs or rationales | high | mitigate | Excerpts are `LogExcerpt` (sanitized, at most 4096 bytes) inside blocks labelled untrusted; rationales are `SafeText::inline`, cut to 200 bytes; every block uses a content-derived fence the content cannot forge; user notes sit last under a heading that gives them priority; total caps per section; the fence test proves a forged end marker stays inside its block |
| T-06-03-02 | Information disclosure | Held-out metric leakage (adaptive overfitting) | high | mitigate | `History` stores rendered rows only; rows read only `JudgeSpec::gates` and `Objective::metric`, never `held_out`; scorecard-shape reasons render without a metric name; the non-interference property and the absence test prove it |
| T-06-03-03 | Tampering | Nondeterministic prompt bytes (PromptHash, replay) | medium | mitigate | Inputs sorted by total keys (`(generation, exp)`, `(ordinal, text)`), BTreeSet surface order, fixed number formatting; golden plus SHA-256 pin and a permutation property |
| T-06-03-04 | Denial of service | Prompt growth from long runs or huge logs | medium | mitigate | `HISTORY_GENERATIONS`, `HISTORY_TABLE_MAX_BYTES`, `EXCERPTS_MAX_BYTES`, `STEER_NOTES_MAX_BYTES`, the surface cap, and `MAX_PROMPT_BYTES` (below the CLI's 10 MB stdin cap) |
| T-06-03-05 | Repudiation | Lossy rendering hiding a bad surface file | low | mitigate | A missing, non-UTF-8, or oversized surface is a typed `PromptError`, never a lossy render |
</threat_model>
