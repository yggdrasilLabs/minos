<objective>
Build the two byte paths of a launch on the host: the per-job input disk the backend writes from blob bytes (with the per-launch token), and the receiver that reassembles the guest's authenticated chunks.

Purpose: D-15 (the backend writes the input disk; the runner passes IDs only), D-13 (bytes come through `BlobSource`), GUEST-04 (a byte-capped tar over vsock, authenticated by the token so a candidate cannot forge it), and KRUN-04 (read-only disk inputs only).
Output: input_disk.rs v2, chunks.rs, their tests, and the CLAUDE.md protocol text.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| blob store -> backend | Blob bytes enter the job directory under caps |
| guest processes -> output socket | Any guest process can connect; only PID 1 has the token |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-13-01 | Spoofing | Candidate forging the output stream | high | mitigate | Per-launch token from /dev/urandom, only in the input disk header; receiver refuses any wrong-token connection as ChunkProtocol and raises the fault flag |
| T-05-13-02 | Information disclosure | Token leaking through logs, config, argv, or a blob | high | mitigate | new_token's value goes only to write_input_disk and the receiver; ChunkToken has no Display and a redacted Debug |
| T-05-13-03 | Tampering | A runner bug pairing the wrong job with a plan | high | mitigate | fetch_parts recomputes the LaunchKey and checks role, base, diff, budgets, and memory before writing |
| T-05-13-04 | Denial of service | Connection floods, empty connections, trickling connections | medium | mitigate | Per-connection byte cap and 5 s deadline; reassembler's connection and byte caps; any of these is a candidate fault that ends the run |
| T-05-13-05 | Tampering | Overwriting or reusing an input disk | medium | mitigate | 0600 temporary file in the 0700 job dir, persist_noclobber, deleted with the job dir |
</threat_model>
