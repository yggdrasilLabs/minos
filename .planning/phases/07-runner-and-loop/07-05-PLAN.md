<objective>
Make a conflicting append an error the type system will not let a caller ignore, and give the store a whole-run exclusive lock that both implementations honour.

Purpose: D-08 turns `Appended::Conflict` into `StoreError::Conflict`, so the driver stops naming the run, seq, and event kind instead of carrying on past a bug. LOOP-06 needs a run lock that the loop can test on `MemoryStore` (LOOP-09) and that the production `FileStore` enforces across processes; locking is storage-specific, so it belongs here (07-RESEARCH Pattern 7).
Output: The changed `Appended`, two new `StoreError` variants, the `RunLock` trait with both implementations, and contract tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| driver process -> ledger | Every effect is appended under a content key; a conflicting append means a bug and must stop the driver |
| one minos process -> another | Two drivers on one run would interleave appends; the run lock separates them |
| filesystem -> store | `driver.lock` lives in the user's project; a planted symlink must not redirect it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-05-01 | Repudiation | A resumed step rewriting history with a different record | high | mitigate | `Err(StoreError::Conflict { seq })` writes nothing, is non-retryable, and cannot be ignored with `?`; first write wins in both stores (D-08) |
| T-07-05-02 | Tampering | Two drivers interleaving appends on one run | high | mitigate | `RunLock` with `File::try_lock` on `driver.lock` (released by the kernel on crash) and a `BTreeSet` in memory; contract-tested on both stores (LOOP-06) |
| T-07-05-03 | Tampering | Symlink planted at `driver.lock` | medium | mitigate | Opened through `open_or_create`, which runs the store's symlink and inode checks; a test plants one and expects `Unsafe` |
| T-07-05-04 | Denial of service | Holding the append lock across a VM run blocks `minos stop` | medium | mitigate | `driver.lock` is a separate file; `ledger.lock` is held only inside `append`; a test appends while the run is locked (Pitfall 11) |
| T-07-05-05 | Denial of service | A panic in a guard's drop on a poisoned mutex | low | mitigate | The memory guard ignores poisoning in `Drop`; `lock_run` maps poisoning to `StoreError::Poisoned` |
</threat_model>
