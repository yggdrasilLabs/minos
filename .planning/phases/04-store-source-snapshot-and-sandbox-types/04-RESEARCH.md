## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Source snapshot: paths, entries, exclusions, caps
- **D-01:** `RelPath` stays as Phase 3 built it (ASCII `[A-Za-z0-9._+-]` per component, no leading `-`, no `.` or `..`). A project file whose path falls outside the grammar fails the pack with an error that lists every offending path; the user excludes it in `.minosignore` or renames it. The output tar reader (SBX-05) inherits the same grammar for entry names. No change to `minos-core`, and every CORE-02 rejection stays.
- **D-02:** The clean-tree check (CLI-11) execs the user's own `git`, read-only, on the user's own working tree: `std::process::Command` with `env_clear()` plus a minimal allowlist (as the `claude` provider does), argv `git -c core.hooksPath=<unusable path> --no-optional-locks status --porcelain` or an equivalent read-only form the planner verifies, never a shell. Non-empty output means dirty. Not a git repository, no `git` on the allowlisted `PATH`, or a non-zero exit all count as dirty, so `--allow-dirty` is required to proceed. This does not violate "no git in the trusted path": that rule exists because git on a candidate-controlled tree brings hooks and config into the trusted path, and the user's working tree is never written by a candidate (`adopt` writes a patch file only). Git never contributes to the tarball; the tarball is built from the filesystem walk alone.
- **D-03:** The tarball holds regular files only. A tracked symlink, hardlink, device, FIFO, or socket that is not ignored or excluded fails the pack with an error listing each such entry. Nothing is skipped silently and no link is followed, so the snapshot never differs from the tree in a way the user did not see.
- **D-04:** Four exclusion sources apply at pack time, as a union: `.gitignore` (through the `ignore` crate with `require_git(false)`, so it applies without a repository), `.minosignore`, the manifest's `[source] exclude`, and the hard denylist (D-07). `program.md`, `minos.toml`, and the Dockerfile are packed like any other file unless excluded. `minos.lock` is never packed. Because Phase 3's WR-04 fix requires every judge path to lie under a `[source] exclude` entry, applying `exclude` at pack time is what keeps the judge program out of the candidate's tree.
- **D-05:** Snapshot caps are fixed constants with reasons, never user-tunable: total bytes, file count, per-file bytes, and the existing path caps. A tree over a cap fails the pack naming the largest offenders. Claude picks the numbers (the input disk is 1 MiB today in `input_disk.rs` and grows in Phase 5). Per `limits.rs`'s own rule ("Later plans do not edit this file"), the constants live at the top of the module that enforces them, in the same style; the user's intent is "fixed in code", not a particular file.

#### Secret scan and hard denylist
- **D-06:** A secret-scan hit blocks the pack. There is no override in v1: no manifest allowlist, no CLI flag. The error names the file, the pattern, and the line, never the matched bytes. `--allow-dirty` has no effect on the scan or the denylist.
- **D-07:** The hard denylist is fixed in code and cannot be overridden by an ignore file or the manifest: `.git/`, `.minos/`, `.claude/`, `.aws/`, `.ssh/`, `.env*`, `*.pem`, `id_*` (SSH private keys), `minos.lock`, and every judge path the manifest's judge argv names (already excluded by the WR-04 rule; the denylist makes it independent of the manifest). Each entry is a constant with its reason, following PITFALLS.md Pitfall 28.
- **D-08:** The scan uses a fixed set of high-signal, anchored patterns, each a bounded `regex` (linear time) with a test vector that must hit and a near-miss that must not: PEM private-key headers, AWS access key IDs, GitHub `ghp_`/`gho_`/`github_pat_` tokens, Anthropic `sk-ant-` keys, OpenAI `sk-` keys, Slack `xox` tokens, three-part base64 JWTs, and Google `AIza` keys. No entropy heuristic in v1: the repo's own golden SHA-256 vectors would trip it.
- **D-09:** The scan covers exactly the files that survive D-04 (the files that will be packed), scanning their bytes as-is, binary files included (PEM headers hide in blobs). A secret in an ignored or excluded file never blocks. A file over the per-file cap already failed the pack before the scan.

#### Store layout and durability
- **D-10:** The file store is project-local under `<project>/.minos/`: `runs/<run-id>/ledger.jsonl` (one JSONL file per run) and `blobs/sha256/ab/cdef…` shared by every run of the project. Judge data pushed by `minos judge push` (Phase 7) lands in the same blob store. `.minos/` is on the hard denylist (D-07), so a project's history never enters its own snapshot. A flag to relocate the root is not in v1.
- **D-11:** Ledger locking is per run and per append: `FileLedger::append` takes `std::fs::File::lock` on `runs/<run-id>/ledger.lock` around read-and-rebuild-the-key-set, check the key, write one line, fsync, unlock. Any process (`run`, `steer`, `stop`) can append safely. Phase 7's whole-run `driver.lock` (LOOP-06) is a separate file on top of this; it is not this phase's concern.
- **D-12:** Every append is durable before it returns: write the line with its trailing newline, then `sync_data` (and fsync the directory when the file is created). The write count per run is small, so there is no "sync only before irreversible actions" mode.
- **D-13:** A torn final line (no trailing newline, or an incomplete JSON object at the tail) is tolerated: `read` returns every complete line that passes `Line::verify` and reports the torn tail as a count, never its bytes; the next locked `append` truncates the file to the last complete line before writing. An invalid or torn line anywhere but the tail, a `Line::verify` key mismatch, a non-contiguous `seq`, and an unknown `v` tag are hard errors that refuse the ledger. The key set is rebuilt from the file under the lock on each append, so no process holds a stale index.

#### Sandbox types and the untrusted reader
- **D-14:** Untrusted output carries the role in its type. `Running<R: Role>::wait` returns `Untrusted<GuestOutput<R>>`, and `into_scorecard` is implemented only for `Untrusted<GuestOutput<Judge>>`, so a candidate's bytes have no path to a `Scorecard` and the runner never checks a role at runtime (GUEST-04 enforced by the compiler). A fifth `trybuild` case proves that `into_scorecard` on candidate output does not compile. `into_log_excerpt` and `into_diff_texts` (SBX-04) exist for every role.
- **D-15:** The launch key hashes the judge version for every role: `LaunchKey = IdHasher::new("minos/launch/v1").digest(exp).u64(role tag).digest(judge).u64(trial)`, matching `Judged`'s key fields (exp, judge, trial). A rejudge under a new judge version is a new launch and never reuses a cached result. Role tags are explicit match arms (Candidate 1, Judge 2; 3 reserved for Agent), never discriminant casts. The key gets a golden vector like every composite ID.
- **D-16:** The output tar reader's fuzz corpus (SBX-05) is a committed directory of hostile tar fixtures (path traversal, absolute path, an 8 GB size header, a million-entry stream, symlink and hardlink and device entries, PAX and GNU long-name headers that disagree with the ustar name, a PAX header that desyncs the next entry, a truncated archive), each replayed by a `#[test]` that asserts the exact rejection, plus a `proptest` strategy that generates arbitrary tars and asserts the reader never panics, never allocates past its caps, and never writes to disk. No `cargo-fuzz`: libFuzzer is C++ and `deny.toml` refuses `cc`. The corpus runs under the five gate commands.
- **D-17:** A `SandboxSpec` carries IDs and digests, not bytes: the root `ImageDigest`, the input disk's `BlobId` (written by the host from the base tarball, the canonical diff, and the job JSON, without unpacking or applying anything), the `JobBudget`, the machine size (vCPUs and memory MiB, bounded by constants), and the `LaunchKey`; `SandboxSpec<Judge>` adds the judge-data `BlobId` through its one extra method. `seal` freezes it into a `LaunchPlan` with read-only accessors and no network field; `preflight(host, plan) -> Result<Cleared, Vec<Refusal>>` is the only constructor of `Cleared`, which owns the plan; `Backend::launch(&self, ok: Cleared) -> Result<Self::Running<R>, LaunchError>`; `Running::wait(self) -> Result<Untrusted<GuestOutput<R>>, InfraError>` under the plan's hard maximum duration; dropping a `Running` destroys the VM. Backends read blobs by ID.

#### Carried forward (decided in earlier phases or the design of record; not re-opened)
- v1 is synchronous. No `minos-*` crate depends on tokio; the `Ledger` and `Blobs` traits are plain synchronous traits, and the ledger lock is `std::fs::File::lock` (CLAUDE.md Code rules; `.claude/CLAUDE.md` decision 10). This supersedes `.planning/research/ARCHITECTURE.md` Pattern 3 and Anti-Pattern 4, which argued for async traits before the AWS milestone was deferred.
- The ledger wire format is frozen: JSONL `Line { seq, key, record }`, `Record::V1`, `Line::verify` on every line read, an append whose `EventKey` already exists is a no-op, unknown `v` refused (Phase 3 CORE-08; `crates/minos-core/src/ledger.rs` module docs).
- `BlobId` and `TreeId` are the plain SHA-256 of content, never domain-separated; blob paths are `blobs/sha256/ab/cdef…` (ARCHITECTURE.md Anti-Pattern 6; `.claude/CLAUDE.md` Question 3). Blob writes hash while copying to a temp file in the same directory, `sync_all`, `rename`; reads rehash and refuse a mismatch and a size over the caller's cap.
- Tarball headers are hand-built `Header::new_ustar()`: `set_path`, `set_size`, mode `0o644` or `0o755` (only the executable bit kept), uid and gid 0, mtime 0, `Regular`, empty user and group names, `set_cksum`. Never `HeaderMode::Deterministic` (mtime 1153704088). Paths walked with `ignore::WalkBuilder` (`require_git(false)`, `add_custom_ignore_filename(".minosignore")`, `follow_links(false)`, `hidden(false)`) and re-sorted into a `BTreeSet<RelPath>` before packing (`.claude/CLAUDE.md` Question 3 and Supporting Libraries).
- The host never calls `tar::Archive::unpack` or `Entry::unpack_in`. Hostile tars are iterated in memory with caps checked before reading: total bytes by counting bytes consumed, entry count, per-entry size from the header, path length and depth through `RelPath`, and a watch on GNU long-name, long-link, and PAX headers before the tar crate buffers them (the `HeaderGuard` discipline in `crates/minos-backend-krun/src/rootfs.rs`). `Untrusted<T>` has no `Deref`, `Display`, `Debug`, or `Clone` (precedent: `GuestBytes` in `supervise.rs`).
- `Cleared` owns the plan and `preflight` is its only constructor, so a `Cleared` for plan A can never authorize plan B and no backend crate can mint one (ARCHITECTURE.md Pattern 4, Amendment A5). The `trybuild` cases from Pattern 4: a `Candidate` spec cannot call `secrets`; `LaunchPlan` and `Cleared` struct literals do not compile outside the crate; `launch` refuses a bare `LaunchPlan`; `Untrusted` refuses `{:?}`, `{}`, `*u`, and `.0`. D-14 adds the fifth.
- Never trait objects, never a backend enum in `minos-sandbox`; the runner is generic over `B: Backend` (CLAUDE.md minos-sandbox; ARCHITECTURE.md Anti-Pattern 7). `minos-sandbox` depends on `minos-core` only; `deny.toml` already confines it to `minos-backend-krun`, `minos-runner`, and `minos-cli`.
- Raw struct with `deny_unknown_fields`, `try_from` into a private-field type, the same constructor for hand-built and deserialized values; typed `thiserror` enums that separate candidate faults from infrastructure failures; `anyhow` only in `minos-cli`'s `main`.
- No `unwrap`, `expect`, or slice indexing anywhere, tests and fixtures included; tests return `Result` and use `?`. No `#[allow]` at all (the C-02 grep). `BTreeMap`/`BTreeSet` wherever order affects output.
- Every plan ends with the five gate commands plus the musl clippy line, then the C-01 and C-02 checks; the phase ends with `cargo clean` (GATE-06).

## Project Constraints (from CLAUDE.md)

These carry the same authority as locked decisions. The planner must verify every task against them.

- `unsafe_code = "forbid"`; `clippy::unwrap_used`, `expect_used`, `indexing_slicing` are `forbid` workspace-wide and in `.cargo/config.toml` `[build] rustflags`. No `#[allow]` or `#[expect]` anywhere, including tests (C-02 grep `grep -rnE '#!?\[allow\(' crates --include='*.rs'` must print nothing). The user's standing rule: no `unwrap` anywhere, ever, including tests and probes.
- `missing_docs = "warn"` and clippy `pedantic` at warn, all turned into errors by `-D warnings`: every public item needs docs; every public fn returning `Result` needs `# Errors`; anything that can panic needs `# Panics`. `allow_attributes = "deny"`.
- Never weaken a security invariant to make something compile or pass. No escape hatch, `pub` field, `Deref`, or temporary bypass on `Untrusted<T>`, `SandboxSpec`, or `LaunchPlan`. If blocked, stop and ask.
- Deserialization is validation: parsed types use `#[serde(try_from = ...)]`; raw input structs use `#[serde(deny_unknown_fields)]`; never `#[serde(flatten)]` on raw structs.
- Validated types have private fields and no setters.
- Errors separate blame: library crates use `thiserror` enums that split candidate faults (an `Outcome`, never retried) from infrastructure failures (retried). `anyhow` only in `minos-cli` `main` (`deny.toml` enforces with a wrapper ban).
- Order must be stable: `BTreeMap`/`BTreeSet` or a sorted `Vec` wherever order can affect output, hashing, or durable operations.
- No C in our own crates; no OpenSSL; no libgit2; no git in the trusted path (D-02 carves out the read-only clean check on the user's own tree and records why).
- No tokio in any `minos-*` crate (`deny.toml` bans it outside `msb-imago`). v1 is synchronous: `std::process`, `std::thread::scope`, `std::os::unix::net`, `std::fs::File::lock`.
- Commands are argv arrays; never build a shell string.
- Supply chain: `Cargo.lock` committed; `cargo deny check` gates every build; new build scripts need a reviewed `[bans.build] allow-build-scripts` entry; `[bans.workspace-dependencies] unused = "deny"`.
- Golden vectors are plain `assert_eq!` against hex literals computed outside the code (with `shasum`/`xxd`, recipe in a comment); golden wire files are insta snapshots plus a SHA-256 pin, and `.config/insta.yaml` sets `update: no`.
- A crate-level `clippy.toml` replaces any ancestor; there is no root `clippy.toml` today. Every `disallowed-methods` entry must be proven to fire once, because a mistyped path only warns.
- Gate commands: `cargo fmt --all --check`; `cargo clippy --workspace --all-targets -- -D warnings`; `cargo test --workspace`; `cargo deny check`; `cargo doc --workspace --no-deps`; plus `cargo clippy -p minos-guest --all-targets --target aarch64-unknown-linux-musl -- -D warnings`; then the C-01 and C-02 checks. `cargo clean` at the end of the phase after verification passes (GATE-06).
- Keep CLAUDE.md current: a decision change edits the relevant section in the same change (here: the Source paragraph for the git carve-out and `.minos/` location, the Workspace section if a crate is added, and the sandbox signatures for `Cleared<R>`).
- Phase 3 test conventions: no `tests/common` module (a shared helper trips `dead_code` in binaries that do not use every helper and no `allow` may silence it), so each test file defines its own `TestResult` and helpers; proptest regression files are committed beside their test file.

## Summary

Phase 4 is three independent libraries on top of a finished `minos-core`: a file and in-memory store, the sandbox type system with its hostile output reader, and the source packer. Every library it needs is already pinned in `[workspace.dependencies]` and present in `Cargo.lock`, and `cargo deny check` passes today with them (run 2026-10-14: `advisories ok, bans ok, licenses ok, sources ok`). No new registry package is required. The work is almost entirely about exact semantics, and each one was checked against the pinned source or a probe rather than taken from memory.

The three findings that most change the plan:

1. **Use `tar::Entries::raw(true)` for the output reader, not a `HeaderGuard`.** In tar 0.4.46 raw mode returns every header as an entry with its own typeflag and does no GNU long-name, long-link, PAX, or sparse preprocessing (`archive.rs` `next_entry`: `if self.raw { return self.next_entry_raw(None) }`). Our guest writes plain ustar, so the reader refuses every typeflag except `b'0'` and every non-ustar magic before reading a byte of data. Extension records are never buffered, and the PAX-desync class (GHSA-3pv8-6f4r-ffg2) cannot occur because nothing is applied to the next entry. Combined with taking the reassembled stream as a `&[u8]` checked against a total cap first, every allocation is bounded by the input length.
2. **The snapshot is plain ustar, which limits a path to 255 bytes and a final component to 100 bytes.** `Header::set_path` on a ustar header splits at a `/` into prefix (155) and name (100), and fails otherwise (probe: a single 101-byte component fails). `Builder::append_data` would silently fall back to a GNU `././@LongLink` entry, so the packer must use `Builder::append(&header, data)` and refuse a path that does not fit, listed with the D-01 offenders.
3. **`git status` alone cannot prove the snapshot is clean.** The walker honors only `.gitignore` and `.minosignore` (D-04), but git also honors `.git/info/exclude` and the user's global excludes. A file ignored only there (macOS `.DS_Store` is the common case) is packed while `git status` reports clean. The clean check must also prove that every packed path is tracked (`git ls-files`).

**Primary recommendation:** Build a new `minos-source` library crate for the packer, scan, and clean check; implement `minos-store` and `minos-sandbox` exactly as sketched below; drive every rejection with a test that asserts the exact error variant; and pin every new hash (launch key, snapshot tarball) with a hex literal computed outside the code.

## Architectural Responsibility Map

The tiers here are the crates of a local CLI system, not web tiers.

| Capability | Primary Tier | Secondary Tier | Rationale |
|------------|-------------|----------------|-----------|
| Ledger append, read, lock, torn-tail repair | `minos-store` (file impl) | `minos-core` (`Line`, `Line::verify`, `EventKey`) | Core owns the frozen wire format and keys; the store owns I/O, locking, durability |
| In-memory `Ledger`/`Blobs` for tests above the store | `minos-store` (memory impl) | — | The loop (Phase 7) is tested against it (LOOP-09); it must pass the same contract tests |
| Content-addressed blobs | `minos-store` | `minos-core` (`BlobId::of`) | Plain SHA-256 IDs come from core; the store adds atomic write and verified read |
| Role typestate, `SandboxSpec`, `seal`, `LaunchPlan` | `minos-sandbox` | `minos-core` (`ExperimentId`, `JudgeVersion`, `JobBudget`, `ImageDigest`, `BlobId`, `IdHasher`) | Policy enforced when a spec is built; backends only see sealed plans |
| `preflight` and `Cleared` | `minos-sandbox` | backend crates supply `Capabilities` | `Cleared` must be minted where no backend can mint it |
| `Untrusted<T>`, output tar reader, three exits | `minos-sandbox` | `minos-core` (`RelPath`, `Scorecard::parse_json`, `LogExcerpt`, `Reason`) | Hostile bytes stay wrapped until a core validating parser takes them |

### Pattern 1: Synchronous store traits

**What:** Plain synchronous traits, `&self` methods, no supertraits. Both implementations are `Send + Sync` (assert with a generic `fn is_send_sync<T: Send + Sync>()` test). Static dispatch only.

```rust
// Sketch; verify names against the code as you write it.
pub trait Ledger {
    /// Appends `record` to `run` unless a record with the same key exists.
    fn append(&self, run: &RunId, record: Record) -> Result<Appended, StoreError>;
    /// Every complete, verified line of `run` in `seq` order, and the number of torn tail lines dropped (0 or 1).
    fn read(&self, run: &RunId) -> Result<LedgerRead, StoreError>;
}

#[must_use]
pub enum Appended {
    New { seq: u64 },
    Duplicate { seq: u64 },   // same key, identical record: the STORE-03 no-op
    Conflict { seq: u64 },    // same key, different record: still not written; the caller has a bug
}

pub trait Blobs {
    fn put(&self, bytes: &[u8]) -> Result<BlobId, StoreError>;
    /// Refuses a stored size over `max` before reading, then rehashes.
    fn get(&self, id: &BlobId, max: u64) -> Result<Vec<u8>, StoreError>;
    fn contains(&self, id: &BlobId) -> Result<bool, StoreError>;
}
```

`StoreError` (thiserror, `#[non_exhaustive]`) separates `Io(#[source] io::Error)` (retryable infrastructure), `Corrupt { line: u64, kind: CorruptKind }` (refuse; needs a human: `UnknownVersion`, `BadJson`, `KeyMismatch`, `SeqGap`, `LineTooLong`), `BlobTampered { id }`, `BlobTooLarge { id, size, max }`, `BlobMissing { id }`, `Poisoned`. None of these is an `Outcome`. Every variant carries IDs and numbers only, never file bytes.

`MemoryStore`: `Mutex<BTreeMap<RunId, Vec<Line>>>` and `Mutex<BTreeMap<BlobId, Vec<u8>>>`. Map `PoisonError` to `StoreError::Poisoned` (fail closed; `lock().unwrap()` is forbidden anyway). Never hold the guard across another call. [CITED: rules/own-mutex-interior.md]

### Pattern 2: File ledger append and read

Layout under the store root (`<project>/.minos/`, created with `DirBuilderExt::mode(0o700)`): `runs/<run-hex>/ledger.jsonl`, `runs/<run-hex>/ledger.lock`.

**Append** (D-11, D-12, D-13):
1. `create_dir_all(runs/<hex>)`; if the directory or the ledger file was created, fsync the parent directory after the first write.
2. Open `ledger.lock` (`create(true).write(true).truncate(false)`), `lock()` (exclusive, blocks).
3. Open `ledger.jsonl` with `OpenOptions::new().read(true).append(true).create(true)`. Never `File::create`, never `truncate(true)`.
4. Read the whole file; split on `\n`. Every complete line goes through the validation in "Read" below. A tail with no trailing `\n` is the torn tail: remember its start offset.
5. If torn: `file.set_len(start_of_torn_tail)` then `sync_data`. This is the only mutation of existing bytes, and it removes only bytes no `append` ever reported as written.
6. Compute `key = record.event().key(run)`; if a line has that key: return `Duplicate` if `line.record() == &record`, else `Conflict`. Nothing is written.
7. `let line = Line::new(next_seq, run, record)`; `let mut bytes = serde_json::to_vec(&line)?; bytes.push(b'\n'); file.write_all(&bytes)?; file.sync_data()?;`
8. Unlock (or drop the lock file handle).

**Read:** take `lock_shared()` on `ledger.lock` so a concurrent append cannot be observed half-written as a mid-file line. For each complete line: refuse over `MAX_LEDGER_LINE_BYTES` (recommend 1 MiB; a `Judged` line with 64 metrics is a few KiB); parse a version probe first (Pitfall 3); then `serde_json::from_slice::<Line>`; `line.verify(run)`; require `line.seq() == index` (seq starts at 0, as the core golden `line_v1` shows). A missing ledger file reads as zero lines (the fold then reports `FoldError::Empty`).

**Why read-and-rebuild per append is fine:** a run has hundreds to low thousands of lines; rebuilding the key set is O(n) per append and removes any stale index across processes (D-13).

### Pattern 5: Hostile output tar reader

```rust
pub fn read_output<R: Role>(stream: &[u8]) -> Result<Untrusted<GuestOutput<R>>, OutputFault>;
```

Algorithm, each step checked before the data it guards is touched:
1. `stream.len() > MAX_OUTPUT_STREAM_BYTES` → `TooLarge(Stream)`. `stream.len() % 512 != 0` → `Invalid(NotBlockAligned)`.
2. `let mut archive = tar::Archive::new(Cursor::new(stream)); let entries = archive.entries()?.raw(true);` Raw mode does no long-name, PAX, or sparse processing. [VERIFIED: tar-0.4.46 `src/archive.rs` `next_entry`]
3. Per entry: count; over `MAX_OUTPUT_ENTRIES` → `TooLarge(Entries)`. `header().as_ustar().is_none()` → `Invalid(NotUstar)` (refuses v7 and GNU-format headers). Typeflag byte (`header().as_old().linkflag == [b'0']`, an array compare, no indexing) else `Invalid(EntryType)`: this one check refuses directories, symlinks, hardlinks, devices, FIFOs, `L`, `K`, `x`, `g`, and `S` (sparse) before their data is read. `header().size()?` over `MAX_OUTPUT_ENTRY_BYTES` → `TooLarge(Entry)`. Path: `path_bytes()` → `str::from_utf8` → `RelPath::try_from` else `Invalid(Path)` (rejects `..`, absolute, empty, backslash, NUL, non-ASCII, over-length, over-depth). Running total over `MAX_OUTPUT_FILE_BYTES` → `TooLarge(Total)`. Read with `entry.take(size).read_to_end(&mut Vec::with_capacity(min(size, 64 KiB)))` and require exactly `size` bytes (`Invalid(Truncated)`). Duplicate name → `Invalid(Duplicate)`.
4. After the iterator ends: drop it, `archive.into_inner()` gives the `Cursor`; the tar crate stops at the first all-zero block, so require that block exists (position advanced past a zero block, else `Invalid(NoEndMarker)`: the truncated-archive case, which tar treats as a clean EOF when the stream ends on a header boundary) and that every remaining byte is zero (`Invalid(TrailingData)`).
5. Map any `io::Error` from the tar crate (bad checksum, bad octal) to `Invalid(Malformed)`; the input is in memory, so no error here is infrastructure.

`OutputFault` has a `fn reason(&self) -> Reason` mapping to the existing core variants `Reason::OutputInvalid` and `Reason::OutputTooLarge` (Pitfall 8 says reject, never retry). [VERIFIED: crates/minos-core/src/outcome.rs]

Recommended caps (constants at the top of `output.rs`, each with its reason):

| Constant | Value | Reason |
|---|---|---|
| `MAX_OUTPUT_FILE_BYTES` | 16 MiB | Logs are capped by the guest (console cap 1 MiB today), a scorecard is 4 KiB, a diff 1 MiB; 16 MiB is 4096 chunks of 4 KiB, whose throughput is unmeasured (S03-ANSWER) |
| `MAX_OUTPUT_ENTRY_BYTES` | 8 MiB | One artifact; keeps one entry from taking the whole budget |
| `MAX_OUTPUT_ENTRIES` | 1024 | Bounds per-entry work and the `BTreeMap` |
| `MAX_OUTPUT_STREAM_BYTES` | `MAX_OUTPUT_FILE_BYTES + (MAX_OUTPUT_ENTRIES + 2) * 1024` | One header and up to 511 padding bytes per entry, plus the two end blocks |
| `MAX_DIFF_TEXTS` | 16 (`BATCH_MAX`) | One diff per proposal in a batch |

```rust
walk.standard_filters(false)          // off: hidden, parents, .ignore, git_ignore, git_global, git_exclude
    .git_ignore(true)                 // .gitignore files at every level inside root
    .require_git(false)               // apply .gitignore without a repository
    .add_custom_ignore_filename(".minosignore");
walk.hidden(false).follow_links(false).same_file_system(true)
    .sort_by_file_path(|a, b| a.cmp(b));   // nice to have; the BTreeMap below is the determinism
walk.filter_entry(move |entry| !pruned(entry));   // denylist names, [source] exclude, judge paths
```

- `standard_filters(false)` turns off `parents` (so a `.gitignore` above the project root is not read), `.ignore` files (an undisclosed fifth source), and the global and `info/exclude` git sources, so the four D-04 sources are exactly what applies. The probe showed a parent `.gitignore` and a `.ignore` file had no effect, `.git` was pruned, a symlink arrived with `path_is_symlink() == true`, and a FIFO arrived as neither file nor dir.
- `filter_entry` takes `Fn(&DirEntry) -> bool + Send + Sync + 'static`, so clone the exclude list and judge paths into the closure. It prunes a directory before descent, so `.git/` and `.minos/` contents are never read.
- In the main loop: depth 0 is the root (skip); directories are skipped (empty directories are not represented in a files-only tarball); everything else must be a regular file: `symlink_metadata` first (a symlink, FIFO, socket, device, or `nlink() > 1` hardlink is a D-03 offender), then `File::open`, then `file.metadata()` and require the same `dev`/`ino` (`std::os::unix::fs::MetadataExt`) and still a regular file, then read through `take(MAX_SNAPSHOT_FILE_BYTES + 1)`.
- Collect every offender (grammar, type, ustar fit) before failing, so one error lists them all (D-01, D-03). Show a non-grammar name through core `SafeText::inline` so control characters cannot reach the terminal.
- Mode: `metadata.permissions().mode() & 0o111 != 0` → `0o755`, else `0o644`.
- Store the read bytes in `BTreeMap<RelPath, (Vec<u8>, bool)>`; scan exactly these bytes (D-09), then pack in map order.

Header recipe (probe: two identical packs are byte-identical; two files give a 3072-byte tarball with no 10240-byte record padding):

```rust
let mut builder = tar::Builder::new(Vec::new());
for (path, (data, exec)) in &files {
    let mut header = tar::Header::new_ustar();      // magic "ustar\0", version "00", mtime 0
    header.set_path(path.as_str())?;                // ustar prefix+name split; Err if it cannot fit
    header.set_size(u64::try_from(data.len())?);
    header.set_mode(if *exec { 0o755 } else { 0o644 });
    header.set_uid(0);
    header.set_gid(0);
    header.set_mtime(0);
    header.set_entry_type(tar::EntryType::Regular);
    header.set_cksum();                             // last, after every field
    builder.append(&header, data.as_slice())?;      // writes the header as given; never append_data
}
let tarball = builder.into_inner()?;               // writes the two zero end blocks
let tree = TreeId::of(&tarball);
```

Username and group name are already all-zero in a fresh `new_ustar()` header (probe: `username_bytes() == Some([])`). [VERIFIED: probe, tar-0.4.46 `src/header.rs`, `src/builder.rs`]

| Constant | Value | Reason |
|---|---|---|
| `MAX_SNAPSHOT_FILES` | 10_000 | Real source trees for an experiment are far smaller; bounds the walk and the tar |
| `MAX_SNAPSHOT_FILE_BYTES` | 16 MiB | Source files and small fixtures; datasets are data blobs, not source |

### Pattern 7: Clean-tree check

```rust
// argv, never a shell; current_dir(root) so pathspec "." means the project directory.
let status = ["git", "--no-optional-locks", "-c", "core.fsmonitor=false", "-c", "core.hooksPath=/dev/null",
              "status", "--porcelain=v1", "-z", "--untracked-files=all", "--", "."];
let tracked = ["git", "--no-optional-locks", "-c", "core.fsmonitor=false",
               "ls-files", "-z", "--cached", "--recurse-submodules", "--", "."];
// env_clear() then exactly: PATH=/usr/bin:/bin:/usr/sbin:/sbin, LC_ALL=C, GIT_CONFIG_NOSYSTEM=1
```

Clean ⇔ `status` exits 0 with empty stdout AND `tracked` exits 0 AND every packed `RelPath` is in the tracked set. Anything else is `Dirty { why }`, which `CleanPolicy::AllowDirty` bypasses (and the scan and denylist still run). Reasons:
- `core.fsmonitor=false`: a repo's `core.fsmonitor` names a program that `git status` runs; turning it off keeps status from executing configured hooks. `core.hooksPath=/dev/null` is belt and braces; `status` runs no hook.
- No `HOME` in the environment: git then reads only the repository's own `.git/config`, so the user's global config (commit signing, global excludes, credential helpers) has no effect and the result does not depend on machine-level settings. `GIT_CONFIG_NOSYSTEM=1` drops `/etc/gitconfig` too.
- The `ls-files` subset check closes the gap between the walker's view and git's: a file ignored by git only through `.git/info/exclude` or a global excludes file is packed but invisible to `status` (Pitfall 1).
- Probe on this machine: the `status` form exits 0 with empty output on this clean repo under `env -i PATH=/usr/bin:/bin`, also with `HOME` unset; in a non-repository it exits 128 (`fatal: not a git repository`), which maps to dirty. [VERIFIED: probe with git 2.50.1 (Apple Git-155)]
- Read stdout and stderr on scoped threads through `take(cap + 1)` (recommend 16 MiB stdout, 64 KiB stderr) so a full pipe cannot deadlock, and poll `try_wait` against a deadline (recommend 30 s); a timeout kills the child and counts as dirty.
- `/usr/bin/git` on macOS is the Xcode command-line-tools shim; it worked under the cleared environment. If git is missing, `Command::spawn` fails with `NotFound`, which maps to dirty (D-02).

### Anti-Patterns to Avoid
- **`tar::Builder::append_data` / `append_path` / `append_dir_all` in the packer:** `append_data` silently emits a GNU long-name entry for a long path; the path variants read file metadata (mtime, uid, mode) from disk, which breaks determinism. Ban them in `crates/minos-source/clippy.toml`.
- **`tar::Archive::entries()` without `.raw(true)` on guest output:** non-raw mode buffers long names and PAX records and applies PAX `size` to the next entry.
- **`OpenOptions::truncate(true)` or `File::create` on the ledger:** the Pitfall 18 warning sign. Truncation happens only through `set_len` to the torn-tail offset under the exclusive lock.
- **`WalkBuilder::max_filesize`:** it silently skips large files; the pack must fail on them instead (D-05).
- **Default `WalkBuilder` filters:** `parents(true)` reads `.gitignore` files above the project root, `.ignore` files apply, and global git excludes apply, so the snapshot depends on files outside the tree and on user config.
- **Literal secrets in source or fixtures:** a literal `ghp_…` or PEM header in a test file trips the scanner on Minos's own tree and can trip GitHub push protection. Build vectors by concatenation at run time (Pitfall 5).
- **A `Debug` derive on `Untrusted`, `GuestOutput`, or `OutputFile`:** it would print hostile bytes; `GuestBytes` in `supervise.rs` is the precedent for implementing nothing.
- **Exposing `SandboxSpec::network`, `LaunchPlan::network`, or any `pub` field to make a test compile:** stop and ask instead (CLAUDE.md).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| gitignore semantics (negation, anchoring, nested files, `**`) | A glob matcher | `ignore::WalkBuilder` | Nested `.gitignore` precedence and pattern rules are subtle; ripgrep's implementation is the reference |
| Linear-time pattern matching over binary files | Substring loops or a backtracking engine | `regex::bytes::RegexSet` + `regex::bytes::Regex::find` | Guaranteed linear time; `RegexSet` does one pass for all patterns |
| ustar header encoding, checksums, octal fields | Byte-level header writer | `tar::Header::new_ustar` + setters + `set_cksum` | The crate's encoding is what every reader expects |
| Atomic file replacement | `fs::write` then `rename` by hand | `tempfile::NamedTempFile::new_in(dir)` + `persist` | Unique temp names, cleanup on drop, same-directory rename |
| File locking | `fd-lock`, `fs2`, or lock files with PID checks | `std::fs::File::lock` / `lock_shared` / `try_lock` | flock semantics, released when the handle drops; std since 1.89 |
| SHA-256 and composite hashing | Any digest code | core `BlobId::of`, `TreeId::of`, `IdHasher` | One hashing path; golden vectors already pin it |
| Text sanitizing for terminal output | An escape stripper | core `SafeText`, `LogExcerpt::from_bytes` | Allowlist renderer with the Trojan Source set, already tested |
| Scorecard validation | A JSON walk | core `Scorecard::parse_json(bytes, limits)` | Checks the byte cap first, then duplicates and finiteness |

**Key insight:** every security-relevant parser this phase needs either exists in core (paths, scorecards, text) or is a pinned crate used in a restricted mode (`raw(true)`, `standard_filters(false)`, `Builder::append`). The new code is glue and caps; the danger is in using a crate's convenient default.

## Common Pitfalls

### Pitfall 1: The snapshot and `git status` disagree on what is ignored
**What goes wrong:** The walker honors `.gitignore` and `.minosignore` only; git also honors `.git/info/exclude` and `core.excludesFile` (often `~/.config/git/ignore`). A macOS `.DS_Store` ignored globally is packed, changes the `TreeId`, and `git status` still says clean.
**Why it happens:** D-04 deliberately limits the walker to tree-local sources for determinism.
**How to avoid:** The `ls-files` subset check in Pattern 7. The error names the packed-but-untracked files and suggests `.minosignore`. Phase 8's `minos init` should scaffold a `.minosignore` with `.DS_Store`.
**Warning signs:** A `TreeId` that differs between two machines on the same commit.

### Pitfall 2: `.minosignore` negation re-includes a gitignored file
**What goes wrong:** `ignore` checks the custom ignore file before `.gitignore` and takes the first match, so `!keep.log` in `.minosignore` re-includes a file a `.gitignore` excludes. The probe confirmed it. D-04 calls the sources a union; this one interaction is not a union.
**How to avoid:** Document it in the module docs and CLAUDE.md Source paragraph. The denylist and `[source] exclude` are applied by `filter_entry` after the ignore matchers, so a negation can never re-include those; the secret scan still covers the re-included file. If the user wants a strict union, reject `!` lines in `.minosignore` (Open Question 5).
**Warning signs:** A file listed in `.gitignore` appearing in the pack report.

### Pitfall 3: Unknown `v` looks like any other JSON error
**What goes wrong:** `Record` is `#[serde(tag = "v")]`; a `"v":"2"` line fails as a generic serde error, indistinguishable from a corrupt line, so the "upgrade minos" error (Pitfall 18) cannot be given.
**How to avoid:** Parse a probe struct first, without `deny_unknown_fields`: `struct Probe { record: RecordProbe } struct RecordProbe { v: String }`. If `v != "1"` → `CorruptKind::UnknownVersion`. Then parse `Line`. Either failure anywhere but the tail is a hard error (D-13).

### Pitfall 4: A same-key, different-record append disappears silently
**What goes wrong:** STORE-03 makes a same-key append a no-op. If the loop re-runs a trial after a crash and gets different metrics, the second `Judged` is dropped with no signal. First write wins, which is right for history, but the caller should know.
**How to avoid:** `Appended::Conflict` (Pattern 1). The fold cannot catch this, because the conflicting record never reaches the file.

### Pitfall 5: Secret test vectors trip the scanner and the forge
**What goes wrong:** A literal AWS key or PEM header in `scan.rs` tests makes Minos's own source tree fail its own scan and can be blocked by GitHub push protection.
**How to avoid:** Build every hit vector with `format!("{}{}", "-----BEGIN RSA PRIV", "ATE KEY-----")` style concatenation; keep near-misses literal. Do not quote a full secret-shaped string in doc comments.

### Pitfall 6: `id_*` excludes ordinary source files
**What goes wrong:** D-07's `id_*` matches `src/id_map.rs` or `id_test.go`, which then vanish from the snapshot (or, if denylist hits are errors, block the pack) and the build fails in the VM.
**How to avoid:** Report every denylist drop in `PackReport` so it is never silent, and confirm the pattern with the user (Open Question 4). Match denylist names ASCII case-insensitively (APFS is case-insensitive by default, so `.ENV` is `.env`).

### Pitfall 7: A valid manifest produces a plan longer than the VMM accepts
**What goes wrong:** Core allows each stage up to 1 hour (`MAX_STAGE_MS`), so a candidate's build plus run can be 2 hours, but `minos-vmm` refuses `max_duration_ms` over 3_600_000.
**How to avoid:** `SandboxSpec::new` computes `max_duration = build + run + BOOT_ALLOWANCE` (Candidate) or `judge + BOOT_ALLOWANCE` (Judge), with `BOOT_ALLOWANCE` = 30 s (matching `HOST_DEADLINE_GRACE` in `supervise.rs`), and returns `SpecError::DurationOverCeiling` above `MAX_LAUNCH_MS = 3_600_000`. Never clamp silently. `minos check` (Phase 8) should surface it early.

### Pitfall 8: trybuild snapshots drift or get written by the gate
**What goes wrong:** A missing `.stderr` makes trybuild write `wip/<name>.stderr` and fail; `TRYBUILD=overwrite` would accept anything. Stderr text depends on the rustc version.
**How to avoid:** Commit every `.stderr`; never set `TRYBUILD` in the gate (same discipline as insta `update: no`); the pinned 1.97.1 keeps the text stable. trybuild copies the workspace `Cargo.lock` into its generated project and does not apply `[workspace.lints]`, so a UI file does not need docs, but it must still contain no `unwrap` and no `allow` (the C-02 grep covers `crates/**/*.rs`, including `tests/ui`). Each UI file must fail for exactly one reason; keep one pass case so a broken fixture cannot make every compile-fail case pass. [VERIFIED: trybuild-1.0.122 `src/cargo.rs` copies `Cargo.lock`; no `lints` handling in its source]

### Pitfall 9: "Never allocates past its caps" cannot be measured directly
**What goes wrong:** Counting allocations needs a `#[global_allocator]`, which needs `unsafe impl GlobalAlloc`, which `unsafe_code = "forbid"` refuses.
**How to avoid:** Prove it structurally: the reader takes a `&[u8]` refused above `MAX_OUTPUT_STREAM_BYTES` before parsing; tar's `read_all` preallocates at most `min(size, 128 KiB)` and `raw(true)` never calls it for extensions; entry reads use `take(size)` after the per-entry cap and preallocate at most 64 KiB. The proptest asserts the outcome invariants (Ok results respect every cap; nothing panics). State this argument in the test's doc comment.

### Pitfall 10: The type system proves API shape, not blob provenance
**What goes wrong:** `JudgeData` and `InputDisk` wrap `BlobId`s. If both have public `new(BlobId)`, a runner bug could pass a judge-data blob as a candidate's input disk; the compiler cannot see it.
**How to avoid:** Phase 4 guarantees what SBX-01 asks: no candidate API accepts `JudgeData`. Add the cheap preflight check that a Judge plan's input differs from its judge data, and record in the module docs that the runner (Phase 7) owns provenance. Open Question 2 covers minting `InputDisk` only from the input-disk writer in Phase 5.

## Open Questions (RESOLVED)

1. **`RunningVm::wait` needs a place for host-observed termination.**
   - What we know: D-17 fixes `wait(self) -> Result<Untrusted<GuestOutput<R>>, InfraError>`. The K7 classification (02-SPIKE-EVIDENCE.md) has three non-infrastructure results the host observes itself: guest decided, `Crashed` (no valid frame, or console cap), and `TimedOut`. None of the latter two is an `InfraError`, and putting them inside `Untrusted` would hide trusted host facts behind hostile-data exits.
   - Recommendation: define `wait(self) -> Result<Finished<R>, InfraError>` with `pub struct Finished<R> { ended: Ended, output: Untrusted<GuestOutput<R>> }` and `pub enum Ended { Exited, Crashed(CrashCause), TimedOut }`. It keeps D-17's intent (hostile output wrapped, infrastructure separate) and avoids changing a published trait in Phase 5. The planner should record this as a refinement of D-17, or keep the literal signature and accept a trait change in Phase 5.
   - RESOLVED: adopted as a refinement of D-17. 04-06 defines `Finished<R>` (host-observed `Ended`, the launch key, the hostile stream; built only from a `&Cleared<R>`), and 04-08's `RunningVm::wait(self)` returns `Result<Finished<R>, InfraError>`.

2. **Who may mint `InputDisk` and `JudgeData`?**
   - What we know: SBX-01 is satisfied by API shape. Provenance of the `BlobId` inside each is the runner's job (Pitfall 10).
   - Recommendation: Phase 4 gives both a public `new(BlobId)` with docs naming the provenance rule, plus the preflight inequality check. Phase 5, which owns the input-disk format, can make `InputDisk` constructible only by the writer that builds the disk image.
   - RESOLVED: 04-03 gives `InputDisk` and `JudgeData` a public `new(BlobId)` whose docs name the provenance rule, and `preflight` refuses a Judge plan whose judge data blob equals its input blob (`Refusal::JudgeDataIsInput`); restricting `InputDisk` is left to Phase 5.

3. **Streaming blobs for large root images.**
   - What we know: core exposes `BlobId::of(&[u8])` only; `from_digest` is private to `id.rs`, so a store cannot build a `BlobId` from an incremental digest without a core change (or by round-tripping hex through `FromStr`, which works but is a disguised constructor).
   - Recommendation: in-memory `put`/`get` for Phase 4 (the snapshot is capped at 64 MiB). If Phase 5 stores root images as blobs, add a core constructor such as `BlobId::from_sha256_stream(impl Read)` that hashes inside core, so no caller supplies a digest.
   - RESOLVED: 04-02 keeps `Blobs::put` and `get` in-memory byte slices for Phase 4; the streaming constructor is a Phase 5 question, listed in CLAUDE.md Open questions by 04-09.

4. **`id_*` in the hard denylist (D-07).**
   - What we know: it catches `id_rsa`, `id_ed25519`, and also ordinary files like `id_map.rs`.
   - Recommendation: ask the user whether to narrow it to `id_rsa*`, `id_dsa*`, `id_ecdsa*`, `id_ed25519*`, `id_ecdsa_sk*`, `id_ed25519_sk*`. Either way, report every denylist drop in `PackReport`. Also ask whether `.netrc`, `.npmrc`, `.pypirc`, `*.key`, `*.p12` belong on the list; D-07 locks the current list, so they are not added without the user.
   - RESOLVED: 04-04 implements `id_*` exactly as D-07 locks it and every drop is reported in `PackReport` (04-07); 04-09 surfaces the narrowing and the extra entries to the user as a CLAUDE.md Open questions bullet.

5. **Strict union for `.minosignore` negations.**
   - What we know: `!pattern` in `.minosignore` re-includes a gitignored file (Pitfall 2).
   - Recommendation: document it (default). Rejecting `!` lines would need our own parse of `.minosignore`; only do it if the user wants the literal union.
   - RESOLVED: 04-07 refuses any `.minosignore` line starting with `!` (`SnapshotError::MinosignoreNegation`, naming the file and line), because a negation there would break D-04's union.

6. **Judge-data hash check at pack time (Pitfall 28 suggestion).**
   - What we know: judge data is stored as a tarball blob, so its `BlobId` is the tarball's hash, not any file's. A per-file check needs per-file digests recorded by `minos judge push` (Phase 7).
   - Recommendation: not cheap now; defer to Phase 7 and record the requirement there (judge push records per-file SHA-256s; the packer takes a `&BTreeSet<BlobId>` of forbidden file digests).
   - RESOLVED: deferred to Phase 7 (JUDGE-01, when `minos judge push` records per-file digests); 04-07 records the deferral in `snapshot`'s doc and in CLAUDE.md's Source paragraph.

7. **Backends reading blobs.**
   - What we know: D-17 says backends read blobs by ID, but `deny.toml` lets only `minos-runner`, `minos-loop`, and `minos-cli` depend on `minos-store`, so `minos-backend-krun` cannot call `Blobs`.
   - Recommendation: a Phase 5 decision (the runner hands bytes or paths to the backend, or `deny.toml` gains a wrapper). Phase 4's `Backend` trait should not take a `Blobs` parameter.
   - RESOLVED: 04-08's `Backend` takes no store; how a backend receives blob bytes or paths is a Phase 5 decision, listed in CLAUDE.md Open questions by 04-09.

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Tar path traversal or absolute path in guest output | Tampering | No unpack; `RelPath::try_from` on every name |
| Tar bomb (8 GB size header, million entries, infinite stream) | Denial of service | Stream, entry-count, per-entry, and total caps checked before reading |
| PAX/GNU header desync, parser differential | Tampering | `raw(true)` + ustar magic + typeflag `0` only; trailing bytes must be zero |
| Symlink/hardlink/device entries | Elevation | Refused by typeflag in output; refused by `symlink_metadata` and `nlink` in the snapshot |
| Secrets in the snapshot | Information disclosure | Denylist, `[source] exclude`, scan of the exact packed bytes, no override |
| Judge program in the candidate tree | Tampering (judge integrity) | `[source] exclude` covers judge paths (WR-04) plus the denylist; `SandboxSpec<Candidate>` has no `secrets` |
| Ledger rewrite or torn write | Tampering / repudiation | Append-only open, exclusive lock, `sync_data` per append, `Line::verify` on read, refuse non-tail corruption |
| Blob tampering on disk | Tampering | Rehash on every `get` |
| Terminal escapes in reported names | Spoofing | `SafeText::inline` for non-grammar names; `RelPath` is printable ASCII by construction |
| Config-driven command execution in `git status` (`core.fsmonitor`) | Elevation | `-c core.fsmonitor=false`, no `HOME`, `GIT_CONFIG_NOSYSTEM=1`, argv only |
