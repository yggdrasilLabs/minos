2. `pub fn parse(text: &str, writable: &BTreeSet<RelPath>, limits: &Limits) -> Result<Diff, DiffError>` as an associated function `Diff::parse`. Stages, in order:
   - Stage 1 (before any parsing): non-empty; `text.len() <= limits.max_diff_bytes()`; no NUL and no CR byte anywhere (LF-only canonical form; a CRLF surface file cannot be edited in v1, a documented limitation); text ends with `\n`; line count `<= limits.max_diff_lines()`.
   - Stage 2, our own line-kind state machine over `text.split_inclusive('\n')` with 1-based line numbers: each section is exactly `diff --git a/P b/P` (P parsed up to the first space, then the whole line must equal that form with the same P), optionally one `index <7-64 lowercase hex>..<7-64 lowercase hex>` line optionally followed by a space and mode `100644` or `100755` (mode `120000` gives `ForbiddenHeader::Symlink`, `160000` gives `ForbiddenHeader::Gitlink`), then `--- a/P` and `+++ b/P` with byte-identical P (`--- /dev/null` or `+++ /dev/null` gives `DiffError::DevNull`), then one or more hunks: a header line `@@ -a[,b] +c[,d] @@` (omitted counts mean 1; any text after the closing `@@` and a space is function context, accepted and later dropped) followed by body lines starting with space, `+`, `-`, a bare `\n` (context), or exactly `\ No newline at end of file`. The state machine reads the header counts and consumes exactly b old-side and d new-side lines before it expects the next hunk header or section, so a deleted line whose content begins with `-- a/` is never mistaken for a file header. Known git extended headers map to `DiffError::ForbiddenHeader { line, header }` with `ForbiddenHeader::{Rename, Copy, OldMode, NewMode, NewFileMode, DeletedFileMode, Similarity, Dissimilarity, Binary, GitBinaryPatch, Symlink, Gitlink}`; any other unexpected line (prose, quoted path, timestamp suffix, trailing text) is `DiffError::UnexpectedLine { line }`. P must parse as RelPath (`DiffError::InvalidPath { line, error: PathError }`).
   - Stage 3: `diffy::patch_set::PatchSet::parse(text, ParseOptions::gitdiff())`; any Err is `DiffError::Malformed` with no diffy message text.
   - Stage 4, per FilePatch (defense in depth): not binary; both modes None; operation is Modify with original `a/P` and modified `b/P`; P is in `writable` by exact RelPath equality (`DiffError::NotWritable { path }`, D-01); each path appears once (`DuplicateFile { path }`); at least one hunk (`NoHunks { path }`); at most `max_hunks_per_file` (`TooManyHunks { path }`); at most `max_diff_files` sections (`TooManyFiles`); no hunk whose old-side line sequence equals its new-side sequence including newline presence (`NoOpHunk { path, hunk }`, D-03); each hunk's new start equals its old start plus the running (inserted minus deleted) delta, using the zero-length conventions from Verified API Facts (`InconsistentNewStart { path, hunk }`); convert diffy's usize ranges with `u32::try_from` (`TooLarge` on failure).
   - Stage 5, line accounting: input lines must equal the sum over sections of 1 (`diff --git`) + 0 or 1 (`index`) + 2 (file headers) + per hunk (1 header + lines + one per line lacking its newline). A mismatch is `DiffError::LineAccounting { expected, found }`.
   Plain unified diffs with no `diff --git` line fail at stage 2 (the first line is unexpected).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output -> Diff::parse | Diff text is hostile (single_shot and sweep proposals, later agentic) |
| Diff canonical bytes -> guest applier, git apply, patch -p1 | A parser differential would let a diff mean different things to the validator and the applier |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02-01 | Elevation of privilege | Diff touching a judge or non-writable file | high | mitigate | Exact RelPath membership in writable (D-01); stage 2 grammar requires byte-equal P on all three header lines |
| T-03-02-02 | Tampering | Parser differential (diffy skips prose, extra lines, mismatched diff --git path) | high | mitigate | Our stage-2 grammar plus stage-5 line accounting reject anything diffy would skip; canonical bytes are what every consumer receives |
| T-03-02-03 | Tampering | Create, delete, rename, copy, mode, symlink, binary patches | high | mitigate | Stage 2 forbidden headers plus stage 4 checks on operation, modes, and is_binary; index-line mode 120000/160000 rejected |
| T-03-02-04 | Denial of service | Oversize diff | medium | mitigate | Byte and line caps checked before diffy runs; hunk and file caps after |
| T-03-02-05 | Spoofing | ExperimentId over raw model text | high | mitigate | ExperimentId::of hashes only canonical bytes produced by our serializer and verified by re-parse |
| T-03-02-06 | Information disclosure / Tampering | Hostile text echoed through errors or Debug | medium | mitigate | DiffError carries numbers and RelPath only; Diff Debug prints no content |
| T-03-02-07 | Repudiation | No-op proposals costing VMs | low | mitigate | D-03 no-op rejection at parse |
