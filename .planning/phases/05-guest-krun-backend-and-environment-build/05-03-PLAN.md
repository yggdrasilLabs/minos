<objective>
Run the Wave 0 VM proofs that 05-RESEARCH requires before the backend depends on three new mechanisms, and record which mechanism each later plan must build.

Purpose: The chunked output protocol (S03-ANSWER) has never carried 16 MiB, and S03-ANSWER asked for its throughput; the console pipe that KRUN-01 calls for has only an allow-default local experiment behind it (05-RESEARCH Pattern 7, A3); and D-14 moves the root image under `<project>/.minos/blobs`, whose ancestors the deny-default profile does not allow (Pitfall 2). Plans 05-07, 05-09, 05-15, and 05-21 read this plan's "Mechanism selections" and take the matching branch.
Output: a minimal, production-direction change to minos-vmm's console path check, the ROOT_IMG ancestor rule, a `chunk_stream` spike step in the guest, three ignored VM tests, and 05-EVIDENCE.md.

This plan uses the Phase 2 spike harness (v1 launch config, the spike guest job protocol, `supervise.rs`), which plan 05-21 retires; the wave0 tests are proofs, superseded by the production VM tests in 05-17 and 05-19. The candidate-uid probe binary that 05-VALIDATION lists under Wave 0 arrives in 05-12, because the spike guest has no candidate stage to run it in (05-VALIDATION.md records the relocation).

Conditional stop (why `autonomous: false`): Tasks 1 and 2 and the console and root-image selections run unattended, but if Task 3 selects `- chunks: stop` (the 16 MiB stream lost data or took more than 15 s), the plan ends at a user checkpoint without changing the protocol, the caps, or any dependency, because S03-ANSWER reserves reassessment for the user. The executor returns a `checkpoint:decision` with the recorded numbers in that case; with `- chunks: proceed` it finishes normally.
</objective>
