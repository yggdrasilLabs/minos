<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user's judge directory -> blob store | Judge data is private; it must be hygienic (no secrets, no links) and bounded before it is stored and later handed to judge VMs |
| user's project -> source tarball and image context | The candidate's view; it must never contain judge data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-08-01 | Information disclosure | Judge fixture copied into the surface or build context (Pitfall 28) | high | mitigate | `snapshot` refuses any non-empty packed file whose SHA-256 equals a pushed judge file, naming every path; `env build` passes the lock's set (D-04, D-20) |
| T-07-08-02 | Information disclosure | Secrets inside pushed judge data | high | mitigate | The same anchored secret scan with no override; hits name file, pattern, and line, never bytes (D-03) |
| T-07-08-03 | Tampering | Symlink, hardlink, or special file in the judge directory | medium | mitigate | The shared walker refuses them as offenders and re-checks identity on read |
| T-07-08-04 | Denial of service | Judge data over the guest's input budget | medium | mitigate | Per-file and tarball caps at `MAX_JUDGE_DATA_BYTES` and a file-count cap; checked on metadata before reading; refused, never truncated |
| T-07-08-05 | Repudiation | A changed source snapshot for existing projects | low | mitigate | Existing pack and refusal tests run unchanged with an empty judge set |
</threat_model>
