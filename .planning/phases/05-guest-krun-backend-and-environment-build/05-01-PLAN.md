<objective>
Add the pure-core pieces the rest of Phase 5 builds on: the VM machine bounds and the D-05 memory budget in `minos-core::limits`, the `[environment] memory_mib` and `scratch_mib` manifest fields with their range and budget checks (D-06), the shared output caps, and the streaming `BlobHasher` that the store's streaming put (D-09) names blobs with.

Purpose: D-06 asks `Manifest::try_from` to check memory "against the `Machine` bounds in `minos-sandbox`", but `minos-core` depends on no internal crate, so the bounds move into `minos-core::limits` and `minos-sandbox` will use them (plan 05-06). D-05 makes the VM's memory a budget (guest reserve + tmpfs scratch cap + candidate allowance). D-09 needs a hashing constructor in core.
Output: limits.rs constants and `candidate_allowance_mib`, manifest fields and `ManifestError::MemoryBudget`, `BlobHasher`, tests, and the CLAUDE.md manifest keys.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| minos.toml -> Manifest::try_from | The user's manifest is input; sizes must stay within bounds the launcher and guest accept |
| streamed bytes -> BlobId | A blob's name must be the digest of exactly the bytes stored |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01-01 | Denial of service | [environment] memory_mib / scratch_mib | medium | mitigate | Range checks against core machine bounds and the D-05 budget rule in Manifest::try_from; a manifest that would starve the guest or the candidate is refused at parse time |
| T-05-01-02 | Tampering | BlobHasher naming | high | mitigate | BlobHasher is the plain SHA-256 with no domain, pinned by a split-invariance property test and the FIPS "abc" vector, so a streamed blob cannot be stored under a different name than its bytes |
| T-05-01-03 | Tampering | Duplicated bounds drifting between core, sandbox, and minos-vmm | medium | mitigate | Bounds defined once in core; minos-vmm restatement stays pinned by the WR-02 paired tests; sandbox switches to core's constants in 05-06 |
| T-05-01-04 | Information disclosure | Error messages | low | accept | Manifest errors carry field paths and numbers only, never manifest text |
</threat_model>
