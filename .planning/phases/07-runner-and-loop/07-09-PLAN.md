<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend (host-observed) -> runner | `Ended` and `elapsed` are trusted host observations |
| guest status and judge scorecard -> runner | Authenticated by the chunk token but parsed as hostile; a guest that exploited its kernel could forge them |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-09-01 | Spoofing | Candidate reports its own timing or resource numbers (LOOP-03) | high | mitigate | `host_usage` takes only `Finished::elapsed` and the plan's `Machine`; clippy bans clock reads in the crate (07-03); 07-12 adds a forged-file test |
| T-07-09-02 | Tampering | Infrastructure failure blamed on the candidate or the reverse | high | mitigate | Pure table with one test per row; setup read before role (CR-02); input, mount, unpack, apply-step, and output setup failures are `Infra`; `ScratchFull` is `Config` (WR-02) |
| T-07-09-03 | Elevation of privilege | Objectives scored despite a failed gate (JUDGE-03) | high | mitigate | `judged_outcome` uses `check_scorecard`, gates first; a test with a 0 gate and a missing objective expects `GateFailed` |
| T-07-09-04 | Denial of service | Panic on an odd status combination | medium | mitigate | A proptest over every combination `GuestStatus::new` accepts; no indexing (lints forbid it) |
| T-07-09-05 | Information disclosure | Error text carrying guest bytes | medium | mitigate | `InfraCause` and `ConfigCause` are closed enums with fixed text, `SetupStep`, and `Refusal` sets only |
</threat_model>
