</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| input disk -> PID 1 | Host-written, validated as hostile |
| PID 1 -> candidate | Root PID 1 hands off to an unprivileged, limited process |
| PID 1 -> host output port | Authenticated chunks; other guest processes can also connect |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08-01 | Elevation of privilege | Candidate running as root | high | mitigate | Fixed uid/gid 64000 for every stage (D-08); the trampoline refuses to run as PID 1 or root (05-12) and can only lower limits |
| T-05-08-02 | Denial of service | Candidate exhausting guest memory, processes, files, or CPU | high | mitigate | RLIMIT_AS = allowance, FSIZE = scratch cap, NPROC 512, NOFILE 4096, CPU = budget + 1 s, CORE 0 (D-05) |
| T-05-08-03 | Spoofing | Unauthenticated output | high | mitigate | ChunkSink encodes every chunk with the per-launch token read from the disk header |
| T-05-08-04 | Tampering | Corrupt or mismatched input sections | medium | mitigate | DiskJobSource uses core's checked decoder and check_role; failures are setup failures (infrastructure), reported with the token when known |
| T-05-08-05 | Information disclosure | Host values in the stage environment | medium | mitigate | STAGE_ENV is a fixed four-key list; PID 1 clears the environment before applying it (05-12); exit_env proves it (05-19) |
</threat_model>
