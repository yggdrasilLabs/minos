Build the loop's building blocks: the run inputs and their start and resume checks, the recorder that classifies append errors and dedupes spends, the batch blob and admission, and the history and parent-tree readers.

Purpose: The driver (07-13) is ordering and glue; every rule that could make a resumed run differ from an uninterrupted one (Pitfalls 1 and 2, D-18) or leak hostile text (D-09) lives in one of these blocks, each tested on `MemoryStore` without a VM (LOOP-09).
Output: Four public modules in minos-loop, one test target, and one golden snapshot.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| blob store (stage logs, rationales, notes) -> prompt | Hostile bytes stored by the runner or a user; reach the model only through `LogExcerpt` and `SafeText` |
| ledger and blobs -> resumed driver | A resumed driver acts on recorded diffs and batches; both are re-validated against their content IDs |
| CLI -> loop (`RunInputs`) | Manifest, base, prices, lock digests; checked against the run's record before any effect |
