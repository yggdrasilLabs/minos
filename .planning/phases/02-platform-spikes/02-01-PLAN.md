### E-9: Job wire format (guest reads `/dev/vdb`)

Header, 20 bytes: magic `MINOSJB1` (8 bytes, hex `4d494e4f534a4231`), version u32 big-endian `00000001`, payload length u64 big-endian. Then exactly `length` bytes of UTF-8 JSON. The disk image is zero-padded to whole 512-byte sectors; the guest reads only header plus `length` bytes. `length` is at most 1048576.

Golden header for the 2-byte payload `{}`: `4d494e4f534a4231` `00000001` `0000000000000002`.

Canonical job JSON (compact; the guest test parses it and 02-05's input-disk golden test embeds it):

~~~json
{"v":1,"vsock_port":1024,"steps":[{"report_boot":{}},{"scratch_roundtrip":{"bytes":65536}}],"finish":"poweroff"}
~~~

Top level: `v` (must be 1), `vsock_port` (1 to 4294967294), `steps` (1 to 64 entries), `finish` (`"poweroff"` or `"return"`).

| Step key | Fields | Limits |
|---|---|---|
| `report_boot` | none (`{}`) | none |
| `connect` | `targets` (array of `ip:port` strings, IPv6 as `[addr]:port`), `timeout_ms` | 1 to 16 targets, each a valid socket address; timeout 1 to 30000 |
| `vsock_connect` | `port` | 1 to 4294967294 |
| `vsock_stream` | `bytes` | 0 to 1073741824 |
| `scratch_roundtrip` | `bytes` | 1 to 67108864 |
| `run` | `argv` (array of strings), `stdout_cap` | 1 to 64 entries, first entry absolute, each at most 4096 bytes and free of NUL; cap 1 to 1048576 |
| `console_flood` | `bytes` | 1 to 1073741824 |
| `hang` | none (`{}`) | none |

### E-10: Status frame (guest to host over vsock, CID 2, the job's `vsock_port`)

Magic `MINOSST1` (hex `4d494e4f53535431`), version u32 big-endian `00000001`, length u64 big-endian, then exactly `length` bytes of compact JSON. `length` is at most 1048576.

Golden: the empty report `{"v":1,"steps":[],"job_error":null}` (35 bytes) encodes to header `4d494e4f53535431` `00000001` `0000000000000023` followed by those 35 bytes.
