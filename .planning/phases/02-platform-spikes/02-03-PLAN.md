<objective>
Give `minos-vmm` its first real `main` (D-01): read a versioned, validated launch config (D-04), check the host files it names, hash libkrunfw, build the VM with msb_krun in one of two boot modes, run a watchdog, and enter the VM. Add the entitlements plist (D-11) and the clippy bans that keep the dangerous msb_krun APIs out (KRUN-02 direction).

Boot modes:
- `root_disk` (the decided path, D-18): the root disk is the raw read-only SquashFS image on `/dev/vda`, `/init` is the guest, and `root=/dev/vda` lands last on the command line through `KernelBuilder::init_path`.
- `initramfs` (negative evidence only, D-18): attach a newc initramfs so 02-06 can record what stock libkrunfw does with it.

Purpose: every VM spike launches through this binary. Its exit codes are the K7 map that Phase 5 uses to tell a guest crash from an infrastructure failure (D-05).

Output: the files in `files_modified`, and `evidence/02-03.md` (V-EXIT, D-PROBE).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Parent process to minos-vmm (argv, environment, config file) | The config is host-written, but the environment and the files it names are checked so a wrong path or injected variable cannot reach the VMM |
| minos-vmm to Hypervisor.framework and libkrunfw | The helper is the only entitled binary and dlopens a kernel dylib |
| Guest to VMM devices | The VMM is the guest-facing attack surface; which devices exist decides what the guest can reach |

### E-2: Validation rules

| `kernel.krunfw`, `disks.root`, `disks.input`, `disks.scratch.path`, `vsock.socket`, `console.path`, `boot.initramfs.path` | absolute; every component after the root is a normal name (no `.` or `..`); no NUL; at most 1024 bytes; all pairwise distinct |

### E-3: Exit codes and stderr lines

| Code | Meaning | stderr |
|---|---|---|
| 0 | the VMM exited on its own (guest power-off, guest reboot or panic, SIGTERM); 02-07 confirms each | `minos-vmm: exit 0` from on_exit |
| 64 | not exactly one argument | usage line |
| 65 | config unreadable, over 65536 bytes, not JSON, unknown field, or an E-2 rule failed | `minos-vmm: error: ...` |
| 66 | preflight: a named file missing, not canonical, or the wrong type; scratch over its cap; console path exists; a forbidden environment variable set | `minos-vmm: error: ...` |
| 67 | libkrunfw or initramfs SHA-256 does not match the config | `minos-vmm: error: ...` |
| 70 | msb_krun refused to build or start the VM before takeover (for example HV_DENIED, a failed dlopen) | `minos-vmm: error: ...` |

### E-4: Fixed kernel arguments (constants in launch.rs, never from the config)

| Boot mode | `KernelBuilder::cmdline` | `KernelBuilder::init_path` | other |
|---|---|---|---|
| `root_disk` | `rootfstype=squashfs ro ignore_loglevel` | `/init root=/dev/vda` | none |
| `initramfs` | `ignore_loglevel` | not called | `initramfs_path(<config path>)` |

Why it works (02-RESEARCH.md Pattern 1): msb_krun builds `DEFAULT <cmdline> root=/dev/root init=<init_path> <krun env> -- <args>`, and Linux keeps the last `root=` and the last `rootfstype=`, so `init_path` carries `root=/dev/vda` past msb_krun's `root=/dev/root`.
